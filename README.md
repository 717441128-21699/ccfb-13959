# 中药粉末显微鉴别系统(TCM Micro-ID)

一套运行在浏览器内的中药粉末显微特征自动识别与药典比对原型。检验员导入显微照片后,
系统在 **GPU 着色器(WebGL2)** 中完成预处理与分割,在 **TypeScript CPU 侧**完成连通域、
形态学描述子、规则分类与药典特征比对,输出最相似的药材排名、逐条依据与掺伪判断,
并支持在图上人工增删改标注。

## 技术栈

- Vite + React 18 + TypeScript(strict)
- WebGL2 + GLSL ES 3.00:全图像处理在 GPU 多遍 ping-pong FBO 中完成,每图仅一次回读
- 零重型视觉依赖:连通域、凸包、距离变换、分水岭、模糊规则分类全部手写,便于审计与调参

## 目录结构

```
src/
  gpu/
    shaders.ts        GLSL 着色器(白平衡/盒式模糊/归一化/Sobel/自适应阈值/形态学/打包)
    GpuPipeline.ts    WebGL2 管线封装(RGBA8 多遍渲染,单图一次 readPixels)
  cv/
    geometry.ts       矩、凸包、轮廓链、棱角锐度、欧氏周长
    segmentation.ts   BFS 连通域 + 形态学描述子 + 面积过滤 + 分水岭拆分入口
    watershed.ts      距离变换 + 局部极大值种子 + 多源洪泛(拆分粘连/重叠结构)
    classifier.ts     分层规则决策 + 模糊隶属度打分(阈值集中,可标定)
    matcher.ts        药典特征比对、Top-N 排名、标志特征加权、掺伪检测
    pipeline.ts       单图编排:GPU → 连通域 → 分类 → 标注/统计
  synthetic/
    generator.ts      参数化合成显微图(七类结构 + 气泡/重叠/碎屑/噪点/染色漂移),自带 GT
  evaluation/
    metrics.ts        IoU/中心距全局贪心匹配、precision/recall/F1、混淆矩阵、属性 MAE
  data/herbs.ts       11 味常用药材药典特征表(数值为占位初值,须用标定标本校准)
  ui/                 React 页面:样品鉴别、合成测试、特征库编辑、设置、标注画布
e2e/e2e.ts            headless 浏览器端到端验证(访问 /e2e.html)
test/                 Vitest 单元测试(几何/分类/比对/评测)
```

## 关键设计如何回应需求

1. **同结构跨药材的细微差异(簇晶棱角尖钝、石细胞纹孔疏密)**
   - `crystalSharpness`(轮廓链顶点夹角)、`pitDensity`(单位轮廓暗穴数)、`vesselKind`
     (五类导管纹式)等细粒度描述子,在 `data/herbs.ts` 中作为每味药的显式约束参与打分。

2. **染色深浅/色调漂移鲁棒性**
   - GPU 端:64×64 降采样回读求灰度世界 RGB 均值 → 白平衡;9-tap 盒式模糊求局部均值 →
     局部对比度归一化。
   - 分类器**只使用几何/纹理量与白平衡后的亮度,不使用色相**,换检验员、换染色批次不改变类别判定。
   - 「合成测试」页提供"染色强漂移"场景(色相 ±45°、亮度 0.55~1.45)专门回归。

3. **两味药掺伪识别**
   - `matcher.ts` 先做主成分排名,再把主成分药典不记载、且数量≥3 的结构群作为"未解释结构",
     对其余药材二次匹配;吻合度 ≥0.45 即报疑似掺伪并给出第二成分与依据。

4. **合成测试图与 GPU 着色器**
   - 生成器按药典形态参数化绘制七类结构,注入气泡、约 25% 重叠、组织碎屑、噪点与染色漂移,
     每张图自带 ground-truth,可自动算准确率,形成闭环回归。

## 运行

```bash
npm install
npm run dev        # 开发服务器
npm run test       # 单元测试(21 个)
npm run build      # 类型检查 + 生产构建
```

端到端验证:开发服务器启动后访问 `http://localhost:5173/e2e.html`,
或在界面「合成测试 / 准确率」页点击"生成并评测"。

## 性能

单张 1024×768 图端到端约 50ms(GPU 约 35ms + CPU 约 15ms,headless Chrome 实测),
30 张约 1.5~2s,显著优于 2 分钟预算。时间统计在结果页"GPU 各阶段耗时"中逐阶段展示。

## 当前状态与达到 90% 准确率的路径(诚实说明)

原型已打通**全部功能闭环**(导入→GPU 分割→描述子→分类→药典比对→掺伪提示→人工改标注→
合成回归),单元测试全绿、生产构建通过。但在当前合成测试集上,端到端结构识别准确率
**尚未达到 90% 目标**,主要瓶颈与迭代路径如下:

- **瓶颈 1:经典 CV 分割在结构接触/重叠时的过分割与错位。**
  分水岭已能拆分大连通体,但碎片上的描述子会失真。下一步应引入真实标注数据微调
  `segmentation.ts` 的面积阈值(当前 120px)与 `watershed.ts` 的种子参数。
- **瓶颈 2:分类阈值基于合成图统计标定,与真实制片存在域差距。**
  `classifier.ts` 所有阈值集中在文件顶部,应用药检所复核过的真实照片混淆矩阵逐类校准。
- **瓶颈 3:药典数值表为像素占位。** `data/herbs.ts` 的直径/锐度/纹孔范围必须用标定标本
  (设置页可填 μm/px 系数)替换,特征库页支持 JSON 批量导入导出。
- 建议演进顺序:合成集常规场景达标 → 染色漂移不退化 → 掺伪召回 ≥70% →
  真实照片小样本校准 → 扩样验收。每次调参都用「合成测试」页回归,防止指标回退。

## 已知工程取舍

- 中间渲染纹理统一用 RGBA8 而非 RGBA32F:部分 ANGLE/headless 驱动下浮点纹理可渲染但
  作为采样源返回 0(已实测复现);8 位精度对二值掩膜/边缘/归一化亮度足够,兼容性最好。
- 二值掩膜纹理使用 NEAREST 过滤,避免双线性插值产生中间灰度破坏形态学 min/max。
- 分类采用可解释规则而非黑盒模型,是为了让每条鉴定结论都能向检验员回溯依据;
  后续若引入神经网络,建议仅作规则引擎的复核通道,保留可解释输出。
